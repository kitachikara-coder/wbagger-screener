## 修正方針（推奨案：その場に clone して入れ替える）

Cowork のファイルアクセス（選択フォルダ＝`株式投資/`）を維持するため、**同じパス `株式投資/wbagger-screener/` を独立リポジトリに置き換える**。親（kabu-monitor）はそのパスを追跡解除して無視する。

### 手順
1. **位置確認**
   `git -C 株式投資 log --oneline -8` で6コミットの範囲を確定。`git show --stat` で各コミットが `wbagger-screener/` 配下だけを触っていることを確認（混入があれば報告して止める）
2. **パッチ書き出し**（prefix を落として書き出す）
   `git format-patch -6 --relative=wbagger-screener/ -o /tmp/wb-patches`
   ※ `--relative` が効かない場合は prefix 付きで書き出し、適用側で `git am -p2` を使う
3. **親から追跡解除**（作業ツリーのファイルは残す）
   `git reset --soft HEAD~6` → `git restore --staged wbagger-screener` →
   `git rm -r --cached wbagger-screener` → `.gitignore` に `wbagger-screener/` を追加 →
   `git commit -m "chore: wbagger-screener を独立リポジトリとして切り出し（親では追跡解除）"`
   ※ 6コミット以前から `wbagger-screener/` が親で追跡されていた場合も、この1コミットで追跡解除される
4. **退避と clone**
   `mv wbagger-screener wbagger-screener.local`
   `git clone https://github.com/kitachikara-coder/wbagger-screener.git wbagger-screener`
5. **移植**
   `cd wbagger-screener && git am -3 /tmp/wb-patches/*.patch`
   （`--relative` を使わなかった場合は `git am -3 -p2`）。
   コンフリクトが出たら **`wbagger-screener.local` の内容を正**として解決（Web UI アップロード版との改行・末尾空白の差が原因になりうる）
6. **一致確認**
   `diff -r --exclude=.git --exclude=docs --exclude=.pytest_cache --exclude=__pycache__ wbagger-screener wbagger-screener.local` が**空**であること。
   `docs/` は clone 側（Actions 生成の実データ）を採用し、`docs/data/decisions.json`・`docs/handover/*`・`docs/設計検討_*.md` は移植分が入っていること
7. **テスト**
   `cd wbagger-screener && python3 -m pytest tests/ -q` 全PASS
8. **後片付け**
   一致確認が済んだら `wbagger-screener.local` を削除。`/tmp/wb-patches` も削除
9. **停止**
   両リポジトリとも `git status` と `git log --oneline -8` を報告し、**push せず止める**

### 代替案（採らない理由も書く）
- `git subtree push --prefix=wbagger-screener` … リモートと履歴が無関係なので force-push が要る。Actions 生成履歴が消え、以後も親に同居し続けて同じ問題が再発する
- Web UI で再アップロード … ファイル数が増え（tests/・manual/・workflows・CLAUDE.md）、コミット粒度も失われる

## 作業ルール

1. 破壊的操作（`reset` / `rm --cached` / `mv`）の**前に** `git log --oneline -8` と `git status` を出力して位置を確認
2. `git reset --soft` の N は**実際の HEAD 位置から数えて**決める（`~1` で届かないことがある）
3. `git add -u` を使わない。追加は対象パスを明示し `git diff --cached --name-only` で目視
4. 想定と違った点（依頼書の誤りを含む）は報告に書く
5. **`git push` は両リポジトリとも行わない**
