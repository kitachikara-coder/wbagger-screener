# 設計検討：ストップ高後の押し目スクリーニング（wbagger-screener）

作成: 2026-09-12 / Cowork → 柴田宏行
対象: `wbagger-screener`（東証グロース＋スタンダード版・https://kitachikara-coder.github.io/wbagger-screener/）
目的: ダッシュボードに売買判断を任せず、「この銘柄を今、自分なら買うか？」を判断する材料を最適な形で揃える。
原則: 分析補助であり投資助言ではない。最終判断・発注は本人。損切り-7%（機械執行）が主役。

---

## 0. 手法の分岐（最初に決めること）

| | A: 大引け判断＋翌日追加（分割エントリー） | B: 押し目から買い下がり |
|---|---|---|
| 損切り | -7%逆指値と両立 | **単一の-7%と矛盾**（下がるほど買い増す）。総量ベースの損切り規則を別途定義しないと成立しない |
| 必要な情報 | 押し目の熟成度・出来高枯れ・当日の切り返し | 段階指値の水準・平均取得単価・総量上限 |
| 検証（4節） | 先着ブラケット(+5%/-7%・5日)でそのまま検証可 | 別の出口設計が必要（B群・別検証） |

**整理**：層A（ふるい一覧）・層B（銘柄カード）の情報は両手法で共通。手法の違いが効くのは「判断ログの項目」と「検証の出口条件」だけ。
**推奨**：現行の運用計画（-7%機械損切り・同時保有2銘柄・1ポジ40〜50%）と整合する **A で一本化**し、B は将来のB群（別検証）として保留。
※ 決定は本人。

## 3. 提案する画面構成

### 層A：ふるい一覧（10〜20銘柄に絞る・全自動）
コード / 銘柄 / 市場 / **ストップ高日** / **高値からの日数** / **高値からの下落率** / **出来高枯れ比（当日・5日平均）** / **売買代金20日平均(億)** / 株価 / 前日比 / 時価総額 / **決算日まで(日)** / **材料分類（手入力・未入力は「未」）** / タブー
既定並び：ストップ高日が新しい順 → 出来高枯れ比が低い順。
フィルタ：市場／下落率レンジ／決算跨ぎ除外／材料分類／検索。

### 層B：銘柄カード（クリック展開・チャートで見えない情報だけ）
- 材料の内容（2〜3行）／材料分類（上方修正・大型契約提携・テーマ連想・仕手材料不明）／継続性メモ（1行）＝手入力
- 決算日（確定/推定の区別）
- 信用買残 直近3週の推移・信用倍率と前週比（**Standard必要**）／買残÷浮動株（手入力時のみ・10%超で警告色）
- 出来高推移：S高日=100とした直近10営業日の小棒グラフ
- 下落日の平均出来高 vs 反発日の平均出来高（押し目後）
- 位置要約1行（例「5MA下・25MA上・75MA上・高値-14%」）
- セクター連動：同業種で同日に高かった銘柄数
- 同一銘柄の過去S高エピソード（2年内：S高日→最大押し→N日後）※参考・予測に使わない
- 既存チャート（ローソク足 日/週・MA・MACD・RCI）
- 判断ログ：買う／見送り／理由 → 5営業日後の結果を自動突合

### 削除・非表示
判定◎○△／P.O.列／MACD列／出来高倍列（層Bへ）／自己資本・増益列（層Bへ）。

## 4. 実装前の検証（層Aの抽出条件に根拠を持たせる）

`wbagger-screener/backtest.py` を拡張して実施（既存のS高→前向き評価の枠組みを流用）。
- ユニバース：東証グロース＋スタンダード（現行 backtest.py はグロースのみ→拡張）
- シグナル日 t：直近20営業日内にS高日 s があり、s以降の最高値からの下落率が **-10〜-20%**、かつ **出来高枯れ比（t日÷s日）≤30%**
- エントリー：翌営業日始値 → **+5%利確／-7%損切り先着**（同日両触れは損切り優先）、**5営業日**で時間切れ（終値手仕舞い）
- 比較：同ユニバースの無選別（全日）ベンチ
- 判定：**+5%到達率と平均損益の両方で無選別を上回らなければ、層Aの条件を見直してから実装**
- 感度：枯れ比30/50%、下落率帯を±1段振る（最良値を選び切らない）
- 限界：上場廃止除外の生存者バイアス／日足近似（ザラ場順序無視）／スリッページ未考慮
- 追加API：銘柄あたり日足1回（現行と同じ）＋master1回

## 7. P1〜P3 実装の確定仕様（2026-09-12 追記）

依頼書に書ききれていなかった、実装時に確定させた判定条件・計算式。
**仕様に迷ったら本節が現物**（コードの docstring と一致させてある）。

### 7-1. 母集団（P1）
- `recent_stop_high(jq, uni_codes, target, window=20, cache=None)`。
  `target` を **1日目**として遡り、**データが返ってきた日だけ**を営業日として数える。
  土日は問い合わせない。祝日（空レスポンス）は営業日に数えないので、連休で窓が縮まない
- 同一銘柄が窓内で複数回S高していれば **最新のS高日**を採る（新しい日から遡るため自然にそうなる）
- 暦日の上限は `window*2+12` 日。それでも 20営業日に届かなければ警告を出す
- **母集団はS高銘柄のみ**。旧版にあった「当日 +5%以上の値上がり」は母集団条件から外した
  （`change_pct_min` は `criteria.yaml` に残すが未使用）

### 7-2. 押し目の熟成度（P1）
`dip_metrics(dates, highs, closes, vols, sh_date)` が**銘柄別の調整済み系列から一貫して**算出する。
日付一括スナップショットの値は使わない（S高日〜当日に分割があると基準がずれるため）。

| 項目 | 定義 | 端の挙動 |
|---|---|---|
| 高値からの日数 | S高日以降の最高値(`AdjH`)を**最後に**付けた日から当日までの添字差 | 同値なら新しい方。S高当日は 0 |
| 高値からの下落率 | 当日 `AdjC` ÷ 期間最高値 − 1（%） | S高当日は「終値÷当日高値−1」。**0% とは限らない**（UL=1 は *触れた* の意味） |
| 出来高枯れ比（当日） | 当日 `AdjVo` ÷ S高日 `AdjVo`（%） | S高当日は 100%。分母0は `None`（`—`） |
| 出来高枯れ比（5日平均） | 直近5本の平均 ÷ S高日（%） | 5本に満たなければ在るぶんで平均。S高日が直近5本に入れば含む |
| 売買代金20日平均 | `mean(AdjC × AdjVo, 当日を含む直近20本)` ÷ 1e8（億円） | 20本未満・欠損があれば `None` |

- **算出できない項目は `None` → 画面では `—`。`0%` とは絶対に表示しない**
- 前日比は調整済み系列の `closes[-1]/closes[-2]-1` で出す。日付一括の生値 `C` 同士で割ると
  権利落ち日に「動いていないのに -50%」が出る

### 7-3. 決算日（P1/P2）
- 優先順は **手入力YAML → `/equities/earnings-calendar`**。手入力に `earnings_date_confirmed: true`
  があれば「確定」、無ければ「推定」、API由来は「API」と出し分ける
- `/equities/earnings-calendar` は **`date`/`from`/`to`/`code` を全て無視し、翌営業日発表分だけを返す**
  限定フィード（2026-09-12 実測で受信1件）。**空欄は「発表予定なし」を意味しない**
- 営業日数は **土日のみ考慮・祝日未対応**（多めに出る）。当日は 0、過去日は `None`（＝不明）

### 7-4. 信用残（P2）
- `LongVol`（買残）/ `ShrtVol`（売残）。**信用倍率 = 買残 ÷ 売残**で、日証金の貸借倍率とは別物
- **売残0・欠損の週は倍率だけ `None` にして週そのものは残す**（「売残ゼロ」は消してよい情報ではない）
- 同一日に `IssType` 違いの行が来たら最後の1行を採る
- 取得できない理由を **プラン外(401/403) / 取得失敗(その他HTTP・通信断) / データ無し(200だが空)** に分ける
- 買残÷浮動株は `manual/{code}.yaml` の `float_shares` がある銘柄だけ（10%超で警告色）

### 7-5. 過去の類似局面（P2・参考のみ）
- 同一銘柄の過去2年。S高日から **20営業日以内の終値最安値 ÷ 期間最高値 − 1**（最大押し）と、
  **5営業日後の騰落**を並べる
- 20営業日以内に続いたS高は1エピソードにまとめる。**直近20本に入るエピソードは結果が
  確定していないので出さない**
- **予測に使わない。** 件数が少なく、地合いも違う

### 7-6. 判断ログ（P3）
- 判断日が休場なら「その日以降で最初の営業日」を起点にする
- **5営業日ぶんのバーがまだ無ければ「経過待ち（あとN営業日）」。0% とは出さない**
- `price` を省くと起点日の終値を建値とみなす
- 当日の候補として日足を取った銘柄は系列を使い回す（追加API 0）。候補に無いコードだけ
  取りに行き、**上限30件**で打ち切る。打ち切った分は理由を画面に残す

### 7-7. 既定フィルタ（V0 ゲート）
`criteria.yaml: dip_default_filter` が `false` のあいだは**どのフィルタも既定で絞らない**。
`true` にすると `dip_dd_band` / `dip_dry_max` が**実際に入力欄へ入る**（注記だけ ON にして
絞らない、という状態を作らない）。

**2026-09-12 の V0 実測で不合格**（+5%到達率は 21.2%→35.7% と上回ったが、
平均損益が -0.13%→-0.28% と無選別ベンチを下回った）。→ **`false` で確定**。
下落率・枯れ比は**表示のみ**で、抽出条件・並び順・配点の根拠には使わない。
再挑戦するなら出口条件の再設計を OOS で通してから（数値は `CLAUDE.md` の「重要な検証結果」）。

### 7-8. S高種別（張り付き／一時）（2026-09-13 追記）

`UL=1` は **"Flag of hitting the upper price limit"＝上限に到達した**という意味で、
引けまで張り付いたことを示さない。2026-09-11 断面の当日S高6件のうち3件は終値が
当日高値から二桁下だった（4440 -14.5%／9082 -18.9%／6081 -19.3%）。
**張り付き＝買いが引けまで途切れなかった／一時＝上限で叩かれて戻された**で需給の意味が
ほぼ正反対なので、一覧で見分けられるようにする。

- 判定は `stop_high_kind(high, close)`。**S高日の調整前の生値 `H`・`C`** を使う
  （`UL` が生値ベースのフラグなので、調整後 `Adj*` と混ぜない）
- **張り付き**: `C >= H - 1e-9`（終値＝当日高値）／**一時**: `C < H`
- `H` か `C` が欠損なら **`None`（画面は「—」）**。「一時」に倒さない
- **しきい値は入れない**（「高値の99.5%以上なら張り付き」等）。検証していない恣意的な値を持ち込まない
- 判定は `recent_stop_high()` が既に取得しているバーから読むだけ＝**追加APIリクエスト 0**
- 表示位置は「ストップ高日」列のすぐ右。フィルタ「すべて／張り付き／一時」（既定は**すべて**）と
  ヘッダクリックでのソートに対応。**既定ソートは変えない**（S高日が新しい順 → 枯れ比が低い順）
- バッジは**同系色（青灰）の2色**。緑=良い/赤=悪い は使わない。
  **どちらが有利かは未検証**なので、抽出条件・並び順・配点には一切使わない（B-1/B-2）
- 2026-09-11 実測: **張り付き52件 / 一時38件 / — 0件**

> 下落率は**調整済み**系列で S高日以降の期間最高値から測る（S高日より後に高値を
> 更新していればそちらが起点）。S高種別は**S高日その日の生値**だけを見る。
